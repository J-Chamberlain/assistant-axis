# Stage-1 Multi-Provider Generation Architecture

## Purpose

Stage-1 role-inventory uncertainty analysis tests how stable the generated persona-role manifold is under reasonable variation in generator model and prompt framing. This is a semantic corpus-construction experiment, not an activation-space experiment.

## Provider Separation

Codex owns the OpenAI-side workflow only:

- OpenAI role-inventory generation
- local parsing and normalization
- provider-agnostic ingestion of inventories synced through the repo
- local semantic overlap, topology, and stability analysis
- report and state integration

Anthropic-side generation is not orchestrated locally by Codex. Claude or Claude Code sessions may generate inventories separately and commit or otherwise sync them into `research/stage1_role_inventory_uncertainty/parsed_outputs/` using the common schema.

## GitHub Synchronization Model

GitHub is the synchronization layer between providers. Each provider-specific generation path writes machine-readable inventory files with explicit provenance fields:

- `provider`
- `model`
- `prompt_family_id`
- `timestamp`
- `generation_settings`
- `parsed_role_list`
- `normalized_role_list`

Local analysis scripts read all normalized inventory files present in the repo without assuming they were generated by Codex.

## Why Anthropic Orchestration Was Removed

Cross-provider API orchestration adds unnecessary credential handling, failure modes, and reproducibility ambiguity. Separating provider execution keeps each model family inside its native operating context and makes the analysis layer provider-agnostic. It also avoids requiring `~/.anthropic_api_key` for Codex-side work.

## Reproducibility Requirements

Each generation run should preserve:

- exact prompt-family file
- model identifier
- provider
- temperature
- max token limit
- timestamp
- raw output
- parsed role list
- normalized role list
- any API error payload if generation fails

Generation should use deterministic or near-deterministic settings. The default OpenAI-side temperature is `0.2`.

## Normalization Requirements

Normalization is intentionally conservative:

- lowercase
- trim punctuation
- convert whitespace, slashes, and hyphens to underscores
- collapse repeated underscores
- remove exact duplicates within an inventory

The pipeline must not aggressively merge semantically distinct roles. For example, `editor`, `reviewer`, and `proofreader` remain distinct.

## Current Scripts

- `scripts/generate_role_inventories.py`: OpenAI-only generation and parsing.
- `scripts/load_external_role_inventories.py`: provider-agnostic ingestion of OpenAI, Claude, or manual inventories.
- `scripts/normalize_role_lists.py`: conservative normalized-list construction.
- `scripts/compare_generated_role_manifolds.py`: local overlap and role-family analysis across available inventories.

## Operational Rule

Do not require Anthropic credentials for Codex-side Stage-1 work. If Claude-side outputs are absent, the OpenAI-side pipeline and local analysis should still run and clearly report which providers are represented.
